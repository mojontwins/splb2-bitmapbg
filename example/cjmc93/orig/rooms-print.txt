# CJMC93 rooms: what each room paints over its backdrop.
#
# Format: "room NAME BACKDROP", then statements, one or more per line,
# separated by ": ", until the next "room" line. Everything after a #
# is a comment. The statements are the original's own (taken from the
# decompiled listing, the line numbers are in the comments), so the
# BASIC syntax applies:
#
#   PRINT [#0;] item; item; ...   items: AT row,col | INK n | PAPER n |
#                                 BRIGHT n | FLASH n | INVERSE n | "text"
#                                 "[A]".."[U]" are the UDGs (gfx/tiles.png),
#                                 "[g0]".."[gF]" the block graphics,
#                                 PRINT #0 prints on rows 22-23
#   FOR v=a TO b [STEP s] ... NEXT v      (on one line)
#   LET A$="text"                          (for LEN A$ in an AT)
#
# Besides the BASIC: SOLID row,col,width makes cells solid without
# drawing anything (for walls that are part of a backdrop).
#
# BACKDROP is castle, cave or bridge (gfx/backdrops/*.png) or black.
# After it, a picture can be named (gfx/pictures/NAME.png): it is drawn in
# the game area, under everything else (e.g. "room 1.5 castle corridor").
#
# The colour decides what the player can do with a cell, as in the
# original (which looked at ATTR): PAPER 0 + INK 7 (attribute 7) is free
# space, PAPER 1 + INK 0 (attribute 8) is deadly water, anything else is
# solid. Spaces in attribute 7 inside the play area (rows 0-19, columns
# 4-27) aren't painted at all: the backdrop shows there. FLASH is ignored
# (splib2 uses that bit to keep sprites out of a cell).
#
# The rooms' order, exits and enemies are in src/cjmc93.c (room_info).
